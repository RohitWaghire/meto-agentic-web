# Devpost draft

**Tagline:** An agent that can finish a purchase, but only inside limits you set, with every step, approval, and undo visible.

## Problem

Agent commerce today is a chatbot that might spend your money. The Open Agentic Web asks for something stricter: published networks, a browser runtime, visitor-owned keys, and user-owned writes.

## What we built

meto is a dummy lighting shop plus meto Studio. The concierge network is HOCON data. It runs in the visitor’s browser from the official agentify-website runtime. Otari is the default router; BYOK is on the page. `website_*` tools call the same `App.page` methods as the human buttons. Spend caps live in the page object, not the model. Irreversible calls open a dialog that names the compensating rollback. Undo walks the ledger in reverse; rollback_step reverses only the last entry.

A second origin, meto Freight, quotes dummy delivery windows after consent. A same-origin MCP facade lets other agents register and start a policy-bound checkout (HTTP 402 until a dummy payment signature). Card numbers never appear in tool schemas.

## Differentiation

Not another pizza chatbot. Policy-bound mandates, auditable receipts, and compensating rollback — a slice of the spec’s “transactions, negotiation and arbitration” extension — plus a documented [permissioned site-actions](permissioned-actions.md) pattern others can copy.

## Built with

Astro 5, Node 22, the nsdeploy/agentify-website runtime (Apache 2.0), Neuro SAN HOCON, Otari BYOK.
